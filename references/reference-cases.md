# 已验证的参照案例与实测标尺

这里记录的是**实际跑出来的指纹**，用来给新案例做标定。判读结论必须有参照物；
没有参照物时，只能说"缺乏正向证据"，不能下判断。

---

## 案例 1：佳能 EOS R6 Mark II，RAW 经 Capture One 转出（两组版本对照）

| | `258a7656.jpg`（原始出片） | `258a7656-1.jpg`（二次处理版） |
|---|---|---|
| 色彩采样 | `1x1 1x1 1x1`（4:4:4） | `2x2 1x1 1x1`（4:2:0） |
| EXIF 字节序 | 小端 `II` | **大端 `MM`**（被整体重写） |
| 内嵌缩略图 | 有 | **无**（next-IFD = `00000000`） |
| XMP / APP13 / APP14 | 有 XMP、APP13 | **全无** |
| 量化表 | RAW 转换器自带 | 被换成通用表 |
| 拍摄参数 | 完整 | 被完整复制（连亚秒计数 `86` 都一致） |
| 文件 `Software` | `Capture One Windows` | `Capture One Windows`（复制残留） |
| 块效应（8px） | 1.024 | 1.023 |
| 梯度能量 | 2.555/级 | 2.502/级（比值 **0.979**） |
| 最佳对齐位移 | — | **dy = −17**（零位移时 MAD 16.30 → 对齐后 **2.51**，降 84.6%） |

**结论**：`-1` 是被另一个程序重新编码并整体位移过的版本；画面内容差异极小
（频域中低频能量比 ≈1.000，只有量化步长升到 2/4 的顶频段下降 = 纯编码损失）。

**重要校准**：梯度能量比 **0.979** 对应的是"轻微降噪 + 重新编码"这种量级。
它落在"无差异"带（0.95~1.05）内。**真正的磨皮/精修会让这个比值明显低于 0.95。**
案例 1 早期一度被判为"做了降噪柔化"，后来按频域证据降级 —— 用这个比值回看，
当时的措辞确实过强。

## 案例 2：佳能 EOS 5D Mark IV，机身直出 JPG 经影楼交付流水线

三张（`1U1A1663` / `1U1A1703` / `1U1A1717`），特征完全一致：

**指向"机身直出"的硬标识（伪造不了）**
- 佳能私有 MakerNote 完整：`Firmware Version 1.1.2`、`CanonModelID 0x80000349`
  （ExifTool 官方表 = EOS 5D Mark IV）、内部序列号 `EK0852051`、
  机身序列号 `154055000661`、镜头 `EF50mm f/1.8 STM`、`CropInfo = 0`（未裁切）
- IFD0 **无 `Software` 字段**
- `DateTime` / `DateTimeOriginal` / `DateTimeDigitized` 三者一致
- 时区字段有效（`TimeInfo` 时区 = 480 → UTC+8）
- 无 APP13 / 无 APP14 / 无 `crs:` 调色参数 / 无编辑历史

**指向"被软件动过文件"的三条痕迹（都是交付流水线副作用，不是修图）**
1. XMP 由 `XMP Core 4.4.0-Exiv2` 写入（开源库签名，相机固件不写这个）
2. 内嵌 `platform=MSFT` 的标准 sRGB 配置 —— **与案例 1 的 Capture One 出片字节完全相同**
3. 缩略图被摘掉（next-IFD = `00000000`），而 MakerNote 仍声明缩略图有效区

**一条硬矛盾**：`1U1A1703` 存储像素是 `4480x6720`（竖幅），但 EXIF 与 MakerNote
都声明 `6720x4480` 横幅且 `Orientation=1` → 相机记录横幅、交付文件是竖幅，
元数据未同步，说明该帧在相机写完之后被外部程序旋转过。

**像素实测**：块效应 1.176 / 1.282（相位 0 单峰 → 8px 网格完整，未被缩放）；
量化表近乎无损（亮度表合计 86）；梯度能量 1.495 / 0.903。

## 跨案例的关键对照（最重要的那条）

案例 1 是 **RAW 转出**，案例 2 是 **机身直出**，两台不同相机、相隔数月。
但两者内嵌的 sRGB 色彩配置**字节完全相同**（`platform=MSFT`）。

→ 因此：**"内嵌 ICC 色彩配置"绝不能当作修图证据**。它是交付/转换流水线塞进去的，
出现在每一批文件的每张图上。判定方法是看同一批里是否连不同来源的文件都带同一份配置。

同理，案例 2 说明：**"丢缩略图 + 丢 XMP + 元数据被重写"也可能是流水线行为**，
不能单独用来指控"有人手动修了图"。案例 1 的 `-1` 之所以能定案，靠的是
**三条证据同时成立**（元数据血缘 + 4:2:0 + 17px 整体位移），而不是任何单条。

## 实测标尺（用于交叉校准）

| 指标 | 机身/RAW 转换器直接出片 | 被二次编码 |
|---|---|---|
| 8px 块效应（相位单峰） | 1.02 ~ 1.28 | 1.02 ~ 1.02（精量化会让网格消失） |
| 色度采样 | 4:4:4 或 4:2:0，取决于相机设置 | 常被改成 4:2:0 |
| 零位移 MAD（同一帧两版） | — | 10~20/255 |
| 对齐后 MAD（同一帧两版） | — | **< 3/255** |
| 对齐后 MAD（不同帧） | — | **> 30/255**（这就是"不是同一帧"的门槛依据） |
| 梯度能量比（轻微降噪） | — | 0.98 左右 |
| 梯度能量比（明显磨皮） | — | 预期 < 0.95（未实测到案例，取用时务必目视确认） |

## 已知无法从文件本身确定的事

- **具体是哪个软件**处理的。只能确定编码器类别（libjpeg 系 / Photoshop / Capture One）
  和"最后写元数据的库"（`x:xmptk` 签名），两者都不是"制作软件"。
- **像素是否被改动过**。当量化步长接近 1 时，任何程序用同一套量化表重编码，
  差异小到不可测。要清零这层不确定性，唯一办法是**拿到存储卡上的原始文件做逐字节比对**。
- **自动化增强 vs 人工精修**。同一套指纹可能来自自动画质增强服务，也可能来自人。
